# Agent 与对话

## 一条消息的处理流程

1. **验签与回执**：渠道适配器校验签名并解析消息，网关立即返回平台要求的回执，后续工作交给 `waitUntil` 在后台完成。
2. **去重**：按消息 ID 在 Redis 里 `SET NX`，平台重推的同一条消息只处理一次。
3. **记入历史**：消息加上[消息头](#消息头)后写入会话历史。
4. **群聊采样**：群里没 @ 机器人的消息，每个群每 10 秒最多触发一次模型，其余的只记录。
5. **agent loop**：把系统提示词、历史和工具发给模型，循环执行工具调用，直到模型挂断。
6. **记入回复**：这一轮发出的消息（表情包记为 `[表情包：名字]`，文件记为 `[文件：名字]`）写回历史。

实现见 [`src/agent/handle.ts`](../src/agent/handle.ts) 和 [`src/agent/loop.ts`](../src/agent/loop.ts)。

## agent loop

### 请求

[`loop.ts`](../src/agent/loop.ts) 直接 `fetch` 调用 `POST {OPENROUTER_BASE_URL}/responses`，不依赖 SDK。这样自定义参数可以原样透传，地址也可以换成任何兼容 Responses API 的网关。请求体为：

```
{ model, ...OPENROUTER_EXTRA_BODY, instructions, input, tools, tool_choice: "required" }
```

OpenRouter 的 Responses API 是无状态的，不支持 `previous_response_id`，所以每一步都重放完整记录：上一步返回的 `output`（推理、消息、工具调用）按顺序追加到 `input`，再为每个工具调用追加一条对应 `call_id` 的 `function_call_output`。

### 说话与挂断

模型只能通过工具行动，每次请求都设置 `tool_choice: "required"`：

- **说话**：调用 `send_message`，一次就是一条消息，可以连发几条（每轮最多 5 条，表情包和文件也算）。发消息不会结束这一轮，所以模型可以先说"等我查查"，再去搜索。
- **挂断**：说完后调用 `end_turn`，通常和最后一条消息放在同一步，不会多一次模型调用。旁观时不想说话，就只调用 `end_turn`。
- **同一步的执行顺序**：一步里的所有调用都按模型给出的顺序执行，`end_turn` 放在什么位置都一样，整步执行完才结束这一轮。和告别消息放在同一步的 `remember`、`write_file` 也会生效。
- **发送失败先不挂断**：挂断的那一步里如果有消息发送失败（比如 QQ 的回复期限已过），这一轮就先不结束，让模型看到错误再决定怎么办。
- **兜底**：如果服务商没有遵守 `required`、模型直接输出了文字，私聊或被 @ 时会把这段文字作为一条消息发出去。

| 可选的 `tool_choice` | 含义 |
|---|---|
| `"auto"` | 模型自己决定是否调用工具 |
| `"required"` | 必须至少调用一个工具（本项目的默认设置） |
| `"none"` | 不允许调用工具 |
| `{"type":"function","name":"…"}` | 必须调用指定的工具（本项目在最后一步强制 `send_message`） |

### 步数与时间

- **步数**：一轮最多 40 步，旁观轮次也一样（不插话时只调用 `end_turn`，1 步就结束）。一步就是调用一次模型，模型在一步里可以同时调用多个工具。
- **时间**：函数最长运行 300 秒。剩余时间不足 90 秒时，下一步就是最后一步。
- **最后一步必须发消息**：在输入末尾追加一条系统提示，告诉模型步数或时间用完了；同时把 `tool_choice` 设为 `{"type":"function","name":"send_message"}`，强制它发一条消息说出目前的结果，没做完就说做到哪了。发完本轮一定结束。如果这一轮已经发满 5 条，就直接结束。
- **耗时工具自动缩短**：`bash` 的超时会随剩余时间缩短，保证命令结束后至少还有 15 秒给模型回复。

## 系统提示词

人设写在 [`src/agent/system-prompt.ts`](../src/agent/system-prompt.ts)，修改后重新部署即可生效。每次请求时，代码会在后面追加渠道的格式要求（适配器的 `promptHint`，比如 QQ 要求纯文本）。

每一轮会变化的说明（"这次没人 @ 你""步数用完了"）不写进系统提示词，而是作为一条 `developer` 消息追加在输入末尾，并且不存进历史。这样系统提示词和历史的开头保持不变，能持续命中提示词缓存。

## 消息头

每条用户消息开头都会加一行消息头，并且一起存进历史：

```
[2026/11/03周二 20:43 Asia/Shanghai｜群聊｜发送人 老王 #3B6834｜@你]
大肥鱼你又在摸鱼？
```

- **时间**：让模型始终知道"现在"，不会猜错日期。时区由 `AGENT_TIMEZONE` 设置。
- **发送人**：平台用户 ID 的后 6 位作为编号，群里靠它分清谁是谁；平台提供昵称时一并显示。QQ 只提供每个机器人独立的 openid，同一个人在私聊和群里的编号也不同。
- **`@你`**：群里被 @ 的消息会带上这个标记，没有就是群友之间在聊。

## 历史与缓存

历史以 Redis 列表的形式保存，每个会话一个键。条数上限是**防止资源耗尽的安全阈值，不是给模型的上下文预算**：

- **保留条数**：私聊 100 条，群聊 200 条。
- **分批裁剪**：列表涨到上限的 1.25 倍时，才一次性裁回上限。如果每写一条就裁一次，发给模型的历史开头每次都会变，提示词缓存每次都会失效；分批裁剪后，开头大约每 50 条才变一次。
- **自动过期**：会话 7 天没有新消息就整个删除。
- **手动清空**：发送 `/reset`。
- **图片只存占位符**：历史里的图片记为 `[图片]`，模型只能看到当前这条消息里的图。
- **临时键**：去重记录 1 小时后过期，采样锁在采样间隔结束后过期。
