01 / WORKFLOW · 工作原理

一条群消息怎么走完全程

收消息与跑 Agent 解耦：先毫秒级回执，再在后台围绕只追加事件流运行工具循环。

  1. 01 POST /api/webhook/:channel

    Webhook 进来，立即回执

    验签（QQ 为 Ed25519）、解析载荷、去重入库后马上返回 200 OK。满足平台严苛的回调超时要求，后续任务交由 waitUntil 在后台继续。

  2. 02 Append-Only Event Log

    一切都写进事件流

    每个聊天对应一条只追加的事件流：用户消息、模型输出（含思维链）、工具调用和结果全部原样入库，每一轮模型输入直接从事件流推导。

  3. 03 Single-Agent Lease Lock

    一个会用工具的 Agent

    每一步：读事件流 → 调用模型 → 把输出和工具结果写回。通过会话行租约锁保证同一聊天同一时刻只有一个 Agent 在跑，每次写库均校验锁持有权。

  4. 04 Multi-Turn & Handoff

    从原渠道回复，然后挂断

    支持分几条连发、引用指定消息、发表情包，说完调用 end_turn 挂断。回复过程中群里新来的消息，在下一步循环里就能立刻看到。

02 / ARCHITECTURE · 为什么不需要服务器

平时零开销，只为真正的对话付费

不用买云主机、不用配进程守护，把计算、存储与状态恢复都交给 Serverless 原语。

有消息才运行，超时自动接力

没有常驻进程，没人说话就不消耗算力。临近 Vercel 函数 300 秒时限时自动收尾或签名接力给新的 /api/worker 实例；即便函数中途被杀，下次也能从事件流无损恢复。

部署与存储免费额度即够

Vercel Hobby 加 Supabase、Upstash Vector 免费版即可完整跑通：Supabase 不限 API 请求次数，Vercel Sandbox 超出免费额度只会暂停、不会产生账单扣费。

前缀稳定，97.8% 缓存命中

免费的是部署和存储，模型调用按用量付给 OpenRouter 等供应商。由于事件流只追加、思维链原样回传，提示词前缀完全稳定，线上一轮对话缓存命中率在 97% 以上。

03 / CAPABILITIES · 核心特性

像一个真的群友，而不是一个问答框

专为群聊互动、多模态理解与自主工具调用设计，所有模块均通过清晰的 TypeScript 接口解耦。

  1. 01

    多渠道接入

    支持 QQ（单聊、群聊、频道，Ed25519 验签）、Telegram 与通用 HTTP。所有渠道实现同一适配器接口，新增渠道只需写一个对象。

  2. 02

    一个聊天一个 Agent

    收消息和跑 Agent 解耦。群里几个人同时发消息只会有一个 Agent 回答；锁是会话行上的租约，每次写库都校验锁版本。

  3. 03

    像真人一样聊天

    用 send_message 分多条连发、reply_to 回复指定消息、end_turn 主动挂断、发表情包；还能旁观没 @ 它的群消息，自主判断要不要插话。

  4. 04

    看图、听语音

    聊天图片自动缩放后入库缓存，历史图片随时重看；QQ 语音直接使用平台自带的语音转写文本。

  5. 05

    跨群长期记忆

    基于 Upstash Vector 的语义检索与写入，所有聊天共用一个记忆库，并自动记录每条记忆的来源会话与时间。

  6. 06

    Linux 沙盒工作区

    在 Vercel Sandbox 里安全执行 bash、Python 与 Node.js，每个聊天拥有独立持久盘，能读图、也能把生成的文件发回群聊。

  7. 07

    联网搜索与抓取

    内置网页搜索与正文抓取工具，实时获取最新资讯；另配模型账户余额与额度查询工具。

  8. 08

    任意 Responses API 模型

    直接调用标准 POST /responses，默认接入 OpenRouter。请求体可透传任意参数，如锁定供应商或设置推理强度。

  9. 09

    20 万 Token 自动压缩

    上下文达到 20 万 Token 时自动生成结构化摘要替代旧历史；思维链原样保留回传，确保长对话依然高命中缓存。

04 / QUICKSTART · 快速开始

三步跑起来

无需准备服务器，几分钟内完成 Vercel 部署、数据库初始化与机器人回调绑定。

STEP 1

部署到 Vercel

点击顶部「一键部署」按钮，或者克隆仓库后在终端执行：

$ npx vercel
STEP 2

配置环境变量

配置模型 Key 与渠道凭据，并在 Vercel Marketplace 添加 Supabase 后执行一次 supabase/schema.sql：

OPENROUTER_API_KEY
QQ_APP_ID / QQ_APP_SECRET
SUPABASE_URL / SUPABASE_SECRET_KEY
STEP 3

自检与填写回调

访问 /api/health 确认存储、模型和渠道均已就绪，再到机器人平台后台配置 Webhook 地址：

GET /api/health
{ "store": "supabase", "channels": { "qq": true } }
想换成自己的机器人？ 人设在 src/agent/system-prompt.ts，工具在 src/tools/，渠道适配器在 src/channels/。改一个文件就能换人设。
